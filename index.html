Projects + Scoped Memory

Claude · Available on Pro & Max plans

What it does

Claude Projects creates a persistent workspace where every conversation shares the same uploaded documents and custom instructions. Instead of re-pasting your PRD or competitive intel at the start of every chat, you upload them once and Claude references them automatically from then on — across every session in that project.

Who it's for

PMs who work with Claude repeatedly on the same product and are tired of re-establishing context at the start of every conversation

The PM take

Pros

  • Eliminates the "here's my PRD again" tax — upload it once and every session has full context from the start
  • Research compounds over time: a project on "Q3 pricing strategy" accumulates weeks of decisions and frameworks that Claude can reason across
  • Custom instructions per project mean Claude behaves differently for a "user research" project vs a "sprint planning" one — no more generic responses

Cons / caveats

  • Project Knowledge has a token limit — large doc sets may get silently truncated without warning
  • Doesn't work passively; you have to consciously open the right project before starting a new conversation
  • Pro-only ($20/mo) — not available on the free tier, which limits access for casual users

What real users say

PMs who've adopted Projects tend to describe a clear before/after moment — the first time Claude already knows what they mean by "the onboarding flow" or "the Q2 launch" without being told. The recurring complaint is wishing the context limit were higher for teams with large document libraries. There's also widespread confusion between Projects and Claude's separate Memory feature (which stores facts globally across all conversations) — they solve different problems and are worth understanding separately.

Verdict

If you use Claude more than twice a week on the same product area, Projects will immediately change how useful it feels. Set one up this week: create a project for your current product, upload your PRD and any key research docs, and add a custom instruction like "I'm a PM at [company]. Focus on PM-relevant insights." The payoff compounds — the longer you use it, the more Claude understands your specific context without you having to explain it.

Visual Version History

Bolt.new · Released March 2026

What it does

Visual Version History lets you browse a visual timeline of every previous state of your project and restore any of them with one click — no Git knowledge required. Think of it as an undo button that goes back days, not just one step.

Who it's for

Non-coders and PMs prototyping with AI builders who are afraid to break a working version

The PM take

Pros

  • Removes the biggest psychological barrier to experimenting — fear of breaking something that works
  • No Git setup or command line knowledge needed; purely visual
  • Encourages faster iteration because reverting is instant and risk-free

Cons / caveats

  • Only available within Bolt.new — doesn't replace a real Git workflow for production code
  • Version history depth is limited; long-running projects may not retain every state indefinitely
  • Won't help if your project has already burned through Bolt's free token allowance

What real users say

The most common complaint about Bolt has been token burn — users report exhausting the free tier in 3–4 days of active development. Version History doesn't solve that, but it does address a separate pain that comes up constantly in community forums: the anxiety of making a change and not being able to get back. Several users describe it as the feature that finally made Bolt feel safe to use for real projects.

Verdict

If you're a PM or non-coder using Bolt.new to prototype ideas, Visual Version History is worth turning on immediately — it makes the experimentation loop genuinely lower-stakes. It won't fix Bolt's token costs, but it removes the friction that stops people from trying bold changes. Try it this week before you build anything you'd be upset to lose.
